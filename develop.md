# Разработка

Документ для тех, кто хочет собрать прошивку сам, поменять пины или разобраться, как всё устроено. Пользовательская инструкция — в [README.md](README.md).

## Сборка

Готовые бинарники лежат на [странице релизов](https://github.com/voffmail/edgetx-elrs-usb-sim/releases/latest). Если нужна своя сборка, есть два скрипта:

**Windows** ([`tools/build.ps1`](tools/build.ps1)):

```powershell
.\tools\build.ps1                  # сборка, при первом запуске скачает тулчейн
.\tools\build.ps1 -Clean           # пересобрать с нуля
.\tools\build.ps1 -NoSetup         # без установки тулчейна
.\tools\build.ps1 -Board pico      # сборка под RP2040
```

**Linux/macOS** ([`tools/build.sh`](tools/build.sh)):

```bash
bash tools/build.sh
```

Параметры задаются переменными окружения: `BOARD` (по умолчанию `pico2`), `BUILD_DIR` (`build`).

Результат — `edgetx_elrs_usb_sim.uf2` в корне проекта. Тулчейн (ARM GCC, CMake, Ninja, Pico SDK) скрипты ставят в `.toolchain/` и не прописывают в PATH — он нужен только для сборки.

Для RP2040 собирайте с `-Board pico` / `BOARD=pico`. Для RP2350 в режиме RISC-V — `-Board pico2_riscv`.

### CI

[`.github/workflows/build.yml`](.github/workflows/build.yml) собирает прошивку на каждый push и pull request. На тег `v*` создаёт GitHub Release и прикладывает UF2. Версия Pico SDK задаётся в `env.PICO_SDK_VERSION`, целевая плата — в `env.PICO_BOARD`.

## Настройки в коде

Все основные константы — в начале файлов, менять их просто.

### Пины и UART

`src/main.c`:

```c
#define CRSF_UART uart0
#define CRSF_RX_PIN 29
#define CRSF_TX_PIN 28   /* библиотеке нужен валидный пин, сигнал не используется */
```

TX в этой прошивке не передаёт ничего: CRSF односторонний, приёмник только отдаёт кадры. Но `uart_init()` требует оба пина, поэтому TX должен указывать на существующий вывод. Можно назначить любой свободный.

Если выбран uart0, то из группы 26–29 принимать умеет только GP29 (UART0 RX), а GP28 — это UART0 TX. Поэтому пара 29/28 работает как RX/TX, а не наоборот. У GP26 и GP27 сигналы UART1 выведены на альтернативную функцию F11, так что при желании их тоже можно занять.

Функция вывода выбирается через `UART_FUNCSEL_NUM(uart, pin)` в `src/crsf.c`: SDK сам подбирает основную или альтернативную функцию. Благодаря этому подойдёт почти любой вывод, а не только «канонические» UART-пины.

### Каналы и кнопки

`src/main.c`:

```c
#define CH_ROLL 0
#define CH_PITCH 1
#define CH_THROTTLE 2
#define CH_YAW 3
#define CH_BUTTON_FIRST 4

#define BUTTON_PRESS_OFFSET 150
#define BUTTON_RELEASE_OFFSET 50
```

Порядок AETR: каналы 1–4 идут на оси, каналы 5 и дальше — на кнопки. Смещения задают гистерезис в единицах канала CRSF: кнопка нажимается, когда канал выше центра на 150, и отпускается, когда он падает до центра +50. Если у вашего тумблера маленький ход, уменьшите `BUTTON_PRESS_OFFSET`.

Тангаж инвертируется в `build_report()` (`-channel_to_axis(...)`), потому что в CRSF положительный pitch — это «от себя», а в симуляторах обычно наоборот.

### Число кнопок

`src/usb_descriptors.h`:

```c
#define HID_BUTTON_COUNT 8
```

По умолчанию 8 кнопок (AUX1–AUX8, каналы 5–12). Дескриптор HID и размер отчёта собираются из этого значения: до 8 кнопок — 1 байт, до 12 — 2 байта. Для 8 кнопок отчёт 5 байт, для 12 — 6.

Почему не 12 по умолчанию: ExpressLRS держит верхние каналы под служебные задачи. Непередаваемые каналы приходят как `2047` (`0x7FF`), а канал арма может дублироваться в CH14. Подробнее — в разделе «Разбор кадров».

### Светодиод

`src/led.h`:

```c
#define LED_PIN 22
```

На этой ревизии платы WS2812 висит на GP22, у эталонной RP2350-USB-A — на GP16. Если светодиод не горит, первым делом проверьте пин.

Константы индикации — в начале `src/led.c`:

```c
#define FADE_PERIOD_MS 2000    /* полный цикл «дыхания» без линка */
#define FADE_MAX_LEVEL 96      /* максимальная яркость в этом режиме */
#define LINK_R 0               /* ровный зелёный при линке */
#define LINK_G 64
#define LINK_B 0
#define BLINK_HALF_PERIOD_MS 27  /* мигание при движении стиков, ~19 Гц */
#define BLINK_R 0
#define BLINK_G 48
#define BLINK_B 48
#define MOVE_HOLD_MS 300       /* сколько мигать после остановки стиков */
#define MOVE_DELTA 6           /* порог движения в единицах канала, ~3.8 мкс */
```

Отдельного регистра яркости у WS2812 нет: яркость задаётся значениями каналов (0–255). Цвета — GRB-порядок, как у самой микросхемы.

### Таймаут линка

`src/crsf.c`:

```c
#define CRSF_LINK_TIMEOUT_MS 500
```

Если валидных кадров нет дольше этого времени, состояние переходит в failsafe: кнопки отпускаются, оси встают в центр.

## Как это устроено

### Разбор кадров

CRSF — бинарный протокол поверх UART на 420 кбит/с. Приёмник шлёт кадры вида `адрес | длина | тип | данные | CRC8`. Плата читает байты через прерывание UART, копит их в кольцевом буфере и выделяет кадры типа `0x16` (RC channels packed).

Полезная нагрузка — 22 байта, 16 каналов по 11 бит, упакованных подряд. Распаковка в `crsf.c` идёт побитово: `bits |= byte << shift`, и как только накопилось 11 бит — выдать канал и сдвинуть остаток. CRC8 (полином 0xD5) проверяется на каждом кадре.

Диапазон значений CRSF для каналов — 172…1811, центр 992. Значения вне диапазона считаются отсутствующим каналом и приводятся к центру: так ведёт себя ExpressLRS, который вместо непередаваемого канала кладёт `0xFFFF` (в 11-битном поле — `2047`).

### ELRS и служебные каналы

У ExpressLRS верхние каналы часто заняты: арм, режим полёта, телеметрия. В логах с реального приёмника видно:

```
CH13 = 2047   (не передаётся)
CH14 = CH5    (дублирует арм)
CH15 = 1811   (+100%)
CH16 = 1811   (+100%)
```

Поэтому 8 кнопок — разумный компромисс: каналы 5–12 обычно свободны и управляются тумблерами. Если ваша модель действительно разводит 13–16, поднимите `HID_BUTTON_COUNT` до 12 и проверьте, что каналы не дублируются и не стоят в плюсе.

### USB HID

Дескриптор в `src/usb_descriptors.c` описывает геймпад: 4 оси по 8 бит со знаком (-127…127) и байт(ы) кнопок. VID/PID — `1209:c550` (pid.codes). Отчёт отправляется в `tud_hid_report()` раз в 1 мс, что соответствует интервалу опроса USB Full Speed.

Строки дескриптора: `iManufacturer = CRSF`, `iProduct = EdgeTX ELRS USB SIM`, `iSerialNumber = 0001`. Массив `s_strings[]` индексируется с 1, нулевой элемент зарезервирован под LANGID.

Серийный номер у всех плат одинаковый. Если на одном ПК окажется две платы, udev/`by-id` начнут путаться — тогда стоит подставлять уникальный ID из flash (`pico_get_unique_board_id_string()`).

### Светодиод

WS2812 управляется через PIO: программа `src/ws2812.pio` формирует тайминги 800 кГц, 24 бита на цвет, порядок GRB. Кадр отправляется только при изменении цвета, светодиод держит состояние сам. Обновление раз в 5 мс, поэтому «дыхание» получается плавным.

Логика в `led_task()`: нет линка — синусоидальное затухание 2 с; линк есть — ровный зелёный; движение стиков — мигание с периодом 54 мс и удержанием 300 мс после остановки. Движение определяется по первым четырём каналам с порогом `MOVE_DELTA`, чтобы не мигать от шума.

## Проверка без пульта

`tools/jsmon.py` читает `/dev/input/js*` и рисует оси и кнопки в терминале. Нужен только Python 3, права root не требуются.

```bash
python3 tools/jsmon.py                  # первый найденный js*
python3 tools/jsmon.py /dev/input/js0   # конкретное устройство
```

Скрипт показывает 4 оси полосками и 8 кнопок точками, обновляется вживую, выходит по Ctrl+C. Число кнопок берётся из дескриптора, так что при `HID_BUTTON_COUNT 12` покажет 12.

Альтернативы: `jstest-gtk`, `jstest /dev/input/js0`, `sudo evtest`.

## Ограничения

- Только CRSF на входе. Другие протоколы (SBUS, PPM) не поддерживаются.
- 4 оси и 8 кнопок по умолчанию, 12 кнопок — верхняя граница.
- Телеметрия и данные GPS в USB не передаются: только каналы управления.
- USB Full Speed, интервал опроса 1 мс. Для симуляторов этого достаточно, для точных измерений — нет.
- Прошивка не трогает остальные функции приёмника: биндинг, режимы, телеметрия настраиваются на стороне ELRS.
